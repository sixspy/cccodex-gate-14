# 闸口事件湖仓台

码头闸口扫描先落在贴源层，原文照收。建层员选定业务日，按事件字典把扫描收成明细层：进闸、出闸、倒箱。字典里没有的事件码、箱号不合法或时间读不出的扫描留在剔除清单，不进明细。

这里不管堆存量，只处理扫描事件怎么分层。

## 分区切面

贴源落进湖仓时，分区键必须先钉死切面：不能有的业务日按事件码切、有的业务日按通道切。

| 办法 | 取值 | 分区键 |
|------|------|--------|
| 按事件码切开后落库 | `event` | `event=<事件码>` |
| 按通道切开后落库 | `channel` | `channel=<闸口通道>` |

规矩：

- 分区办法只能二选一；切面选定后即封存，本日禁止改口，全湖沿用同一套切法。
- 分区切面尚未锁死时，这一批不准落库。
- 清洗请求带着的切面跟分区设置对不上，记**分区切面偏了**，混切扫描不落库。
- 两条扫描的切面名只要不为空、又跟封存切法对不上，就进**混切队列**；切面名为空的扫描不进队列。
- 两个建层员对同一批混切同时下手，跨日加锁后只采纳与分区设置相符的切面，后到的记**混切争用**。

页面上四块当场改齐：**分区列表**（事件面数、通道面数、混切次数、办法名）、**切面详情**（同一条扫描按事件码切与按通道切各落在哪个分区，以及实际落点）、**分区设置**（二选一，选后封存）、**混切队列**（每条混切扫描的去向与台账）。业务日与明细行上也直接标出这一批是按事件码切开还是按通道切开。

## 启动

```bash
cd 仓库根目录
docker compose up --build
```

健康检查：`GET http://localhost:8324/api/health`

旧数据卷不带分区切面的表结构，升级后先重置再启动：`docker compose down -v && docker compose up --build`。

## 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/dates` | 业务日清单，带事件面数、通道面数、混切次数、办法名、这一批的切法 |
| GET | `/api/dates/<日>` | 层详情：贴源、明细（带分区键）、剔除、切面详情 |
| POST | `/api/dates/<日>/build` | 收成明细层，可带 `{"method": "event"｜"channel"}` 与分区设置核对 |
| GET | `/api/partitions` | 分区列表、分区设置、混切队列、混切台账 |
| PUT | `/api/partitions/settings` | 封存分区切法，body `{"method": "event"｜"channel"}` |
| GET | `/api/mixed` | 混切队列（可带 `?biz_date=`） |
| POST | `/api/mixed/adopt` | 对同一批混切下手，body `{"biz_date": ..., "facet": ...}` |
| POST | `/api/scans` | 落一条贴源扫描，当场判进不进混切队列 |
